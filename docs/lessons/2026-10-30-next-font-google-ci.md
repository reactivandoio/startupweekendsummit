# `Can't resolve '@vercel/turbopack-next/internal/font/google/font'` / `next/font/google queries have exactly one entry` no build do CI

**Sintoma:** `pnpm build` no CI (runner do GitHub) falha com `Turbopack build failed with 14 errors`, todos em `[next]/internal/font/google/inter_….module.css`: `Module not found: Can't resolve '@vercel/turbopack-next/internal/font/google/font'` e `next/font/google queries have exactly one entry`. Localmente o build passa. Começou entre 22:34 e 22:51 de 29/10/2026 (STA-25 passou, STA-26 já falhou) sem mudança no código das fontes; rodar de novo não resolve.
**Causa:** o `next/font/google` (Next 16.3.5, Turbopack) baixa o CSS do Google Fonts no build e monta um import por arquivo de fonte com a URL na query. A resposta do Google para o runner passou a gerar uma query que o Turbopack não consegue ler (provavelmente URLs de fonte com `&`/`?`, que quebram a query em várias entradas). Depende do que o Google devolve para aquele IP, por isso não aparece na máquina local.
**Correção:** não depender da rede no build. As fontes ficam em `src/app/fonts/*.woff2` (subset latin dos arquivos variáveis do Google Fonts) e o `src/app/layout.tsx` usa `next/font/local` com as mesmas variáveis CSS (`--font-inter`, `--font-inter-tight`, `--font-jetbrains-mono`) e `weight` em faixa (`"100 900"`). Para conferir: `pnpm build` e os arquivos `inter_latin-s.p.*.woff2` em `.next/static/media`.
Evidência: corrigido · Card: STA-27
